# 大改前备份与回滚

## 三种恢复不要混淆

| 类型 | 恢复内容 | 保留内容 |
| --- | --- | --- |
| 前端/代码回滚 | 同一 schema 下恢复旧代码或六个静态文件 | 当前 config、runtime、身份、钥匙串、系统许可 |
| 运行状态恢复 | 一组匹配版本的私密 DB、身份、配置与代码 | 当前 OS、第三方软件；旧任务/租约不能直接继续 |
| 系统组件回退 | root 服务定义、固定厂商包、root ini/manifest 等 | 必须依赖对应管理员备份/系统备份，不只是 GitHub 源码 |

## 重大改动之前

1. 保存本次基线提交 SHA，建立新的开发分支；不要覆盖基线分支。
2. 执行本仓库的只读校验。另用 `tools/private_backup.py --output <受保护目录>` 建立新私密快照并查看缺项。脚本不停止桥接；需要严格一致的整体恢复点时，应另安排维护窗口，确认释放并停止后台后再采集。
3. 私下保留 root 管理员备份、当前第三方软件/许可恢复途径和钥匙串凭据恢复途径。默认用户快照不会获得这些权限，也不会弹 sudo。
4. 如果会改数据库 schema，编写正向迁移、备份与逆向恢复方案。不能依靠旧代码自动兼容未来 schema。
5. 改 Windows 代理前保存各原机 `agent.json` 身份与 `agent.ps1`，只存在原机/私密备份。DPAPI 与节点身份不要复制到另一台机器。

## A. 同机代码回滚

以下只在将来的维护窗口人工操作，本次没有执行：

1. 当前管理台结束共享，等旧目标 fresh 回报 released/absent，确认没有未完成复位、任务或未知提交。做不到就停止恢复，不强制把状态改 idle。
2. 如果只恢复静态页面，完整替换六个静态文件即可，通常不需要重启；保留备份后刷新页面核对。
3. 恢复 Python 代码前，以当前 Mac 用户卸载 `gui/<UID>/com.lumen.bluetoothbridge.controller`；不要停止 Tailscale、切换 USB 或直接关闭 root 服务来代替释放。
4. 从已校验基线恢复 `.py`、`windows/`、`static/` 和必要资源到正式用户安装目录；**保留正式 `config.json` 和整个 `runtime/`**，不要用 `config.example.json` 覆盖。旧代码若不能兼容当前 DB，改走匹配状态恢复。
5. 新代码新增、旧基线没有的文件也要单独移走留备份，防止残留模块混用。不要执行会删除 runtime 的全目录清理。
6. Python root 组件不由这一步更新。若改动涉及该组件，按 C 节审核对应管理员恢复点。
7. 加载原用户 plist，确认只有一个后台；启动恢复会请求释放旧租约，不会自动继续旧共享。等待新心跳后做单台接管/释放验证，再继续日常使用。

### 保留身份的关键

`runtime/admin_token`、`runtime/enrollment_secret`、`bridge.sqlite3` 是同一恢复环境的配套状态；不能从不同日期随意拼接。agent token 在服务端保存为哈希，不能从 DB 反推出客户端丢失的明文 token。源复位 helper manifest 固定引用当前管理身份文件路径；若只改 token 而不同步组件，可能无法健康检查。

## B. 从本地私密归档恢复状态

1. 核验归档 SHA256；在新建的私密目录解包，不能直接覆盖运行目录。归档含秘密，禁止上传本仓库。
2. 先阅读归档 `snapshot-report.json`：时间、DB integrity_check、漏备文件、复制期间是否变化、租约/运行任务摘要。
3. 确保原后台已停止；若迁移到另一台 Mac，确保原节点不能继续同时运行，并重新建立网络/许可/UID 相关组件。
4. 将归档的 `deployment/` 恢复至正式目录，用户目录 0700、私密文件 0600。数据库恢复用 SQLite backup API 或在后台停止后替换完整 DB；**同时移走旧 DB 的 -wal/-shm 文件留档**，不能把新 DB 与旧 WAL 混合。
5. 若快照来自活动中或有 running/queued/unknown 任务，不能直接恢复联网后让后台继续执行。先在副本中审核/隔离任务，未知云提交按 InvokeId 人工核对，不自动重放；原代码不提供跨版本一键灾备任务恢复工具。
6. 对恢复时的旧租约、临时 enrollment、看门狗授权状态做明确处理。启动已有保护只负责请求释放，不能把历史 ready/已验收当成当前事实；无法确认原端释放时不分配新端。
7. 同机原钥匙串继续可用；新机需重新输入外部凭据。网络地址改变时还要更新目标与监测端，参见部署手册。
8. 按验证清单逐项确认；先观察、不批量重装。

## C. 管理员组件回退

源端隔离升级器在 `/Library/Application Support/BluetoothBridge/backups/<时间>-<PID>` 保存 `daemon.plist`、`controller.json` 和 `source.ini`；受限组件安装器在 `reset-helper-...` 保存对应服务定义、manifest、代码等，某些情况下还有原签名 app。

这两类备份不是同一种，参数不能混用。具体使用原 `OPERATIONS.md` 的命令，在正式目录、管理员维护窗口执行，必须先确认空闲。组件安装器要求固定 Apple 解释器、目录归属及已知签名；不要用复制 plist 并运行 sudo 的方式绕过检查。

本次 GitHub 仓库没有 root 许可文件或受限管理员备份内容。用户私密快照遇到 PermissionError 只记录缺项，未扩大权限。如果未来改动系统组件，须另行备份这些 root 材料，才能保证组件级完整回退。

## 不要这样回滚

- 不运行仓库中的旧 `runtime/yorke-repair.txt`、旧 enrollment 或带 Token 安装命令：它们未归档，且可能过期/指向旧节点。
- 不让两个控制器用同一复制身份同时提供服务。
- 不把 `git reset` 当作 SQLite、Windows 或 root 服务的恢复。
- 不把 `taskResult=267009` 当错误；它通常表示计划任务正在运行，仍应核对心跳。
- 不为通过检查关闭签名、摘要、来源绑定、租约或释放确认。

本次验证能证明源文件、归档一致性与隔离自动测试通过，**没有实际执行生产停机回滚或从零灾难恢复**。
