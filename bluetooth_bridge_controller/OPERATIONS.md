# 批量接入与故障处理

2026-11-09 当前状态：正式三轮切换、未授权连接拒绝、代理故障自动恢复、后台重启保护和独立监测均已通过。用户已确认两台试点的手机通行密钥成功；张26随后释放确认通过。现有安装已解除批量保护，实际 `bulk_ready=true`，每批最多 3 台；后续按用户勾选逐台配置，已接入数量以管理台为准，已有凭据无需重新创建。

日常操作：打开 `打开蓝牙控制台.command` → 刷新阿里云列表 → 勾选不超过 3 台 → 选择“首次接入” → 执行。后台自动启动或唤醒、检查环境、分配独立身份、安装并回读版本心跳。已登记电脑选择“更新／修复代理”；异常先用“读取诊断”，结果未知先核对原任务。新增云电脑刷新列表后按同一流程接入，无需逐台登录 Tailscale。

新版页面将日常操作与设备目录分开。进入“电脑管理”可搜索、筛选和翻页；勾选的目标会跨页保留，底部显示完整已选名称。已接入的电脑可“选择使用”，离线时可“唤醒并检查”。唤醒操作完成后再开始使用；它不会自动抢占当前电脑的蓝牙。

“日常使用”的左栏及连接状态图分别显示 Mac USB、私有通道、云电脑枚举和手机验证层级。绿色“共享中”要求代理在线、USB 已连接、蓝牙 ready 且源端就绪；后台失联、代理错误或过期检测结果显示待确认。设备详情中离线回报为最后一次记录。页面每三秒更新，USB 实际检测按既有后台周期运行，页面显示其最近检测时间。手机验证结果无法由驱动 ready 推断。

自动复位组件的范围：`/Library/LaunchDaemons/com.lumen.bluetoothbridge.source-reset.plist` 启动管理员保护的 Python 组件，通过 `/Library/Application Support/BluetoothBridge/reset.sock` 接受当前用户的查询/固定服务复位请求；不监听 TCP。既有 VirtualHere 服务改用保护目录内的完整厂商应用包副本，保留原许可配置、回环监听及单适配器限制。管理员组件不接受自定义命令或服务名；网页和云任务仍由普通用户执行。

每次接管前，状态先进入“正在准备”；这时无电脑获准连接 USB。只有旧电脑确认释放、旧转发连接关闭、受限组件确认新源服务 PID 和端口、目标仍在线且 released/absent 后才开始连接。复位失败会停止本次分配并产生故障通知，不自动重复管理员动作；需在管理台查看错误后重新发起。手动取消或后台重启不会自动继续旧分配。

安装器会打印 `/Library/Application Support/BluetoothBridge/backups/reset-helper-…` 备份路径。需要回退时，先在管理台确认空闲，再由本机管理员运行正式安装目录的 `install_source_reset_helper.py --rollback <该备份目录>`（使用 Apple Command Line Tools Python 和 `-I`），最后重启当前用户的管理后台；它恢复安装前的 USB 服务和控制器配置并停用新增组件。安装未完成时会自动尝试上述恢复。保留具体错误和备份路径以便核对。

当前已实测的基础链路：Mac 外置适配器 → VirtualHere/Tailscale → Yorke / 张26 Windows Server 2025。用户已确认 Yorke 币安手机通行密钥验证成功。下面一次性配置步骤为重新部署参考，现有 Mac 无需重复执行。

## 一次性配置

1. 打开 Yorke，等旧租约释放确认、控制器显示空闲。
2. 当前 Mac 后台已安装。请在访达中双击本目录的 `首次配置管理后台.command`。它会安装**当前用户**的登录后台，并请求一次 macOS 管理员权限，将现有 VirtualHere 服务改为 `127.0.0.1:7576`。控制器在原 Tailscale 地址的 `7575` 按租约转发。仅指定的 `10d7:b012` 设备可共享。
3. 脚本会备份现有服务定义与配置；失败时尝试恢复原服务。管理员密码由本机 sudo 读取，不写进文件或聊天。此步骤不安装新的驱动、网络扩展或系统默认路由。
4. 打开的本地管理台中，进入“连接设置”。保存专用 RAM 用户的 AccessKey ID/Secret，再保存 Telegram Bot Token 和本人私聊 Chat ID。所有凭据写入 Mac 钥匙串，界面不回显。不要将凭据发到聊天或放入代码。
5. 刷新阿里云列表，仅选择 Yorke，任务选择“更新／修复代理”。等待“已确认新版代理在线”。首次安装、修复、诊断是三个独立操作，修复保留原设备身份。
6. 在新版源端隔离下，对 Yorke 再完成一次“分配蓝牙 → 等待正常 → 结束并释放”。后台记录真实接管与释放后才开放批量安装。
7. 先接入第二台，验证切换、拒绝未授权的另一台连接、到期/断网、重启恢复和手机验证，再逐批扩大。默认每批最多 3 台；验证后可调整 `config.json` 的 `max_batch_size`，程序最大允许 50 台、逐台执行。

正式程序与运行数据位于 `~/Library/Application Support/BluetoothBridgeController`，日志位于 `~/Library/Logs/BluetoothBridge/controller.log`，避免桌面目录的后台访问限制。项目旧 runtime 为迁移前留存，当前状态以本地控制台为准。

日常双击 `打开蓝牙控制台.command` 即可打开已认证的本地页面。网页使用一次性启动链接，长期管理令牌不放进浏览器 URL。登录后台独立运行，关闭网页后仍会检查健康状态；停止续期后租约不会无限延长。

## 阿里云权限

为专用 RAM 用户附加本目录 `ram-policy.json`。只用五项操作：查询电脑、查询命令结果、运行本工具脚本、启动、唤醒。这里的 `Resource: "*"` 是这些 ECD API 的授权粒度要求；不能把它描述为云厂商层面对单台电脑的限制。`RunCommand` 本身具有远程执行能力，必须保护好专用用户的密钥。程序只对当前地域列表中明确勾选的电脑下发内置模板。

首次范围是新加坡 `ap-southeast-1`。列表自动发现新电脑；勾选后点击接入，后台完成唤醒、环境检查、一次性入网、安装与版本心跳回读。每台创建独立的一次性接入密钥，不把同一个 Tailscale 身份复制给所有电脑。

脚本提交成功不代表安装完成。只有目标电脑的执行结果和对应版本心跳都满足条件，任务才标记成功。提交回执丢失时标记“结果待核对”，点击“核对原任务”先找回执行记录，禁止盲目重跑。

## Telegram 私聊

在 Telegram 官方 `@BotFather` 创建自己的机器人，向它发送 `/start`。在本地连接设置填写 Token、本人私聊 Chat ID，保存后点击“发送测试通知”，以手机实际收到为准。当前集成只接受私聊，不群发。

告警只包含电脑名称、故障代码和处理建议；不包含密码、代理令牌、通行密钥或认证二维码。持续同一故障只建立一个事件，恢复后通知一次；通知发送失败会有限重试并在管理台显示失败。

Mac 后台每 5 秒检查状态，默认 35 秒没有心跳即判定代理离线。空闲机器的离线提醒会等待云状态回读，以减少正常休眠的误报；活动租约的故障会立即进入释放流程。网络和 Telegram 的送达仍可能有延迟。

正常释放或切换时，原转发连接保留最多 30 秒供 VirtualHere 清理，且不超过原租约到期时间；不接受新连接。旧电脑确认 USB 已释放且蓝牙已消失后才允许下一台接管。故障、过期、代理离线或后台退出不提供这一清理窗口；未收到释放确认时保持等待，禁止强行切换。

**Mac 自身关机、断网或后台卡住**需要独立监测节点。本次用户指定已有 Windows 服务器 203.0.113.20，其 Tailscale 地址为 100.64.0.20。管理员通过 Mac 本地 API `/api/watchdog/enrollment` 为此 Tailscale 地址生成十分钟、单次有效的授权；在服务器下载并校验安装脚本 SHA256 后，以 `-EnrollmentToken` 执行。凭据通过现有 Tailscale 加密通道领取，Telegram Token 不进入安装命令、云任务记录或 Mac 状态数据库。安装器使用 Windows DPAPI 加密并限制为 SYSTEM/管理员可读；不持有 Mac 管理令牌，也不增加远程管理端口。无一次性授权时保留本机隐藏输入的手动方式。

独立监测每 15 秒读取 Mac 的最小健康接口，连续 3 次失败后通知；网络超时和发送耗时会延长实际告警时间。任务以 SYSTEM 开机启动并每分钟检查已退出实例，IgnoreNew 防止重复运行。独立节点向 Mac 回报有限状态，失联超过 90 秒时 Mac 发一次提醒，恢复后通知。Mac 与监测服务器同时断网时，双方均无法发出通知。请不要把会随工作休眠的电脑作为唯一监测节点。

当前独立节点已安装。实际停止 Mac 普通用户后台 70 秒（保留 Tailscale 和系统 USB 服务），远端 48 秒后告警，后台恢复后 16 秒发送恢复通知；随后确认心跳正常、源端和复位组件就绪、租约空闲。该测试没有执行 Mac 断电或监测服务器重启/注销。一次性命令过期时只重新签发授权，不能关闭来源绑定或单次使用检查；安装完成后不要再次运行旧授权。

随后实际合盖休眠也得到交叉验证：17:42:58 休眠、17:43:58 告警；17:47:35 唤醒、17:47:40 恢复通知。Mac 是物理 USB 源，桥接使用期间需保持供电、网络和唤醒；监测负责及时提醒，不能在 Mac 睡眠或关机时继续提供物理蓝牙。

## 常见故障的处理顺序

| 状态 | 首先做什么 | 自动保护或人工边界 |
| --- | --- | --- |
| 已休眠/关机 | 勾选后执行任务，由对应 API 唤醒/启动 | 不重装，保留原身份 |
| 代理离线 | 读取诊断，确认云状态、云助手和 Tailscale | 活动共享进入释放；未确认释放时不切换 |
| 代理启动失败/版本不符 | 使用“更新／修复代理” | 校验摘要与 Windows 语法，保留旧脚本和原身份 |
| USB 不见了/多个同型设备 | 检查 Mac 指定适配器及供电 | 拒绝新的 USB 转发，人工确认硬件 |
| 命令结果未知 | 点击“核对原任务”，保留执行 ID | 不自动重复安装或重新登记 |
| 接管失败 | 读取具体报错、结束会话，再新建会话 | 失败代次被阻止自动重新占用 |
| 网站/手机验证失败 | 确认通行密钥弹窗和手机本人确认 | USB/PnP 成功不能替代手机验证 |
| Telegram 发送失败 | 查看本地告警，验证 Token/Chat ID 并发送测试 | 不把“已入队”当成“手机已收到” |
| 多台同时异常 | 先检查 Mac、Tailscale、USB 源服务和云 API | 不逐台批量重装 |

点击“导出诊断”可导出设备状态、任务执行 ID 和告警。它不导出运行密钥、原始安装命令或云助手原始输出。导出文件仍含电脑名称和网络地址，分享前按实际需要处理。

## 回退与停用

先结束共享并等释放确认。修复前的 Windows 代理保存为 `%ProgramData%\BluetoothBridge\agent.previous.ps1`；代理修复不更换 `agent.json` 身份。Windows 停用可停止名为 `Mac Bluetooth Bridge Agent` 的计划任务，再通过管理台确认设备释放；任务已停止不能代替源端释放确认。

Mac 登录后台停用：`launchctl bootout gui/$(id -u)/com.lumen.bluetoothbridge.controller`。重新启用按首次配置程序处理，避免同时运行两个后台。

源端回退命令应在正式安装目录运行。源端回退备份在 `/Library/Application Support/BluetoothBridge/backups/`，仅管理员可读。使用 `sudo python3 install_source_isolation.py --rollback <该次备份目录>`，再重启本地控制器。脚本先确认无租约、关闭转发端口，再恢复旧服务，避免端口冲突。回退后批量入口将重新关闭。

独立监测节点的任务名是 `Mac Bluetooth Bridge Watchdog`，配置位于 `%ProgramData%\BluetoothBridgeWatchdog`；停用后 Mac 失联的手机通知也会停止。
