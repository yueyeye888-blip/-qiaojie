# Mac 蓝牙桥接控制台

用于把 Mac 上的一只 USB 蓝牙适配器按租约分配给 Windows 无影云电脑，并管理后续批量接入、健康检查和故障通知。

**批量接入入口已开放，默认每批最多 3 台。** 正式三轮切换、未授权连接拒绝、代理故障自动恢复、Mac 后台重启保护和独立失联监测均已实测。用户已分别确认 Yorke 和张26的币安手机通行密钥验证成功。后续接入数量以管理台实时统计为准。

## 新版控制台

界面分为“日常使用、电脑管理、任务进度、遇到问题”。刷新浏览器即可使用新版，启动入口保持不变。

- 日常使用：查看 USB 适配器、桥接通道、当前使用电脑、Windows 蓝牙状态和自动准备组件。页面每三秒读取状态，同时显示 USB 实际检测时间；后台失联后标记“状态未确认”。
- 电脑管理：按名称、ID、主机名搜索，按接入、在线、异常或休眠状态筛选；每页 20 台，列表内部滚动。勾选跨搜索、翻页和刷新保留，每批数量仍由后台限制。
- 已接入但离线的电脑可点击“唤醒并检查”；该操作使用已有只读诊断流程，等待在线后再开始使用，不在后台隐式接管蓝牙。
- 任务进度：查看最近 100 项任务，按状态或电脑筛选。结果未知先核对原任务；未取得提交回执的重试保留同一批次标识。
- 设备详情：查看最近心跳、USB/蓝牙回报、云状态、地址及最后错误。已休眠电脑的旧回报不会被当成实时就绪。

“蓝牙就绪”表示 Windows 已识别适配器；手机连接及通行密钥结果仍以手机和网站提示为准。当前续期规则为网页打开时自动续期，关闭后在现有租约到期时释放；没有沿用参考图中关闭网页后无限续期的文案。

## 接下来怎么用

当前用户已完成本机后台、源端隔离、阿里云、Telegram 和受限自动复位组件的安装，无需重复创建密钥或运行管理员安装器。外置适配器需要每次接管前重启源服务；管理台已自动完成此步骤。

日常打开控制台后选择目标、分配蓝牙，等待“正常”；结束时点击释放，切换时仍须旧电脑确认释放。Windows 代理以 SYSTEM 运行，开机启动，并每分钟检查重启已退出的代理；健康实例不会重复启动。实际终止代理后约 82 秒确认自动恢复，期间共享保护已生效。

临时 [自动复位切换验收.command](自动复位切换验收.command) 保留用于独立排查。该工具本身不安装常驻组件，阶段记录位于正式运行目录的 `runtime/source-cycle-*.jsonl`。

两台试点完成真实验证后，现有安装已解除 `bulk_validation_hold`，管理 API 实际回报 `bulk_ready=true`。新安装的示例配置仍默认保护暂停，不能用复制已通过状态的方式跳过新环境验收。需要单独维护源服务时可运行 [重启USB桥接服务.command](重启USB桥接服务.command)。

完整配置、第二台验收、故障处理和回退步骤见 [OPERATIONS.md](OPERATIONS.md)。权限示例见 [ram-policy.json](ram-policy.json)。日常双击 [打开蓝牙控制台.command](打开蓝牙控制台.command)。

配置完成后的流程：刷新列表 → 勾选电脑 → 一键接入 → 自动启动/唤醒 → 环境检查 → 独立身份入网 → 安装 → 版本心跳确认。默认每批最多 3 台并逐台执行。已有电脑通过“更新／修复代理”保留原身份，结果未知的任务先核对原执行记录。

同一只物理适配器**同时只能分配给一台云电脑**。批量配置表示每台都能轮流使用，不能同时共享同一只适配器。

## 安全与故障边界

- 管理网页仅监听本机；代理接口仅绑定明确的 Tailscale 地址。
- 源端隔离已实际启用，原服务只在本机监听。Yorke 共享期间，未获授权的张26只读连接探测实际被源端关闭。
- Windows 每台持有独立代理令牌，服务端只保存哈希；重装不静默覆盖已有身份。
- 阿里云、Telegram、Tailscale OAuth 凭据保存在 macOS 钥匙串；运行数据和本地配置已忽略 Git。
- Telegram 测试通知已由用户确认手机收到；实际代理故障与恢复测试的六条通知均由 Telegram 确认发送。独立 Windows 监测服务器已部署：暂停 Mac 后台后 48 秒发送失联告警，恢复后 16 秒发送恢复通知，均有远端 Telegram 成功回执。用户另行要求重发测试消息，并已确认手机收到。
- 最近故障会使历史批量验收失效，排队中的新安装也会停止；重新通过真实接管和释放后才恢复。
- 更新脚本校验摘要，异常代次不自动重新占用；未确认释放前不切换设备。
- 正常释放只为原有连接保留最长 30 秒的清理时间，不接受新连接；收到释放确认便关闭。故障、到期、代理离线或控制器退出会中断转发，新目标仍须等待旧目标确认释放。
- 自动复位组件仅通过权限为 0600 的本机 Unix socket 接受当前用户请求；只支持健康查询和重启固定的 USB 服务，不接受调用者指定的路径、服务名或命令。相同请求有持久回执，结果不明不盲目重试，取消和过期的结果不能分配蓝牙。
- 安装器验证 VirtualHere 厂商签名，将完整应用包和组件置于管理员保护目录；管理网页仍以普通用户运行，不设置免密 sudo。安装失败会尝试恢复管理员备份，明确回退方式见操作手册。
- 不修改默认路由，不代替网站登录或手机本人确认；独立固定出口不在本轮验收范围。

## 验证与代码

83 项自动测试通过，覆盖状态机、队列、批量保护、HTTP 边界、实际回环转发、复位前后分配限制、取消/过期/后台重启、重复请求、管理员组件的安全文件读取，以及独立监测的一次性授权、来源绑定和失联通知去重。正式三轮切换、未授权拒绝、代理故障自动恢复、后台重启保护、独立服务器告警及两台手机通行密钥均已实机通过。**Mac 真实断电、监测服务器重启/注销及管理员回退未实测。** 见 [TEST_REPORT.md](TEST_REPORT.md)。

主要代码：`controller.py` 本地 API；`management.py` 任务与告警；`integrations.py` 云与 Telegram；`usb_proxy.py` 租约转发；`windows/` 接入、诊断、修复和独立监测脚本；`static/` 管理页面。

正式运行目录为 `~/Library/Application Support/BluetoothBridgeController`，日志为 `~/Library/Logs/BluetoothBridge/controller.log`。项目中的启动入口会转到正式安装目录；项目旧 runtime 仅为迁移前留存，当前状态以运行中的本地 API 为准。后台不需要完全磁盘访问权限。
